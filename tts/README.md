# Generate speech

Four models. 173 Kitten TTS 2 voices in 20 languages. One simple request. Use
`POST /v1/audio/speech` to generate speech with Kitten TTS 2
(`kitten-tts-2-latest`) or any of the three KittenTTS 0.8 models.
A valid KittenML API key keeps usage attached to your organization. For
pricing, see the [KittenML platform](https://platform.kittenml.com).

## cURL

From the repository root:

```bash
# Complete-response mode writes the finished MP3 after generation completes.
curl -L --fail-with-body -sS \
  https://api.kittenml.com/v1/audio/speech \
  -H "Authorization: Bearer $KITTENML_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{
    "model": "kitten-tts-2-latest",
    "input": "Hello! This audio was generated by Kitten TTS 2.",
    "voice": "eleanor_en",
    "response_format": "mp3",
    "speed": 1.0
  }' \
  --output kitten-output.mp3
```

The success body contains audio bytes, not JSON. The command returns after the
complete MP3 has been saved. Do not pipe binary output to `jq`.

Keep `-L`. When a generation has to wait for hosting capacity, the API answers
with a redirect to a continuation URL; without `-L`, cURL saves an empty file
and still exits `0`. The official OpenAI SDKs follow redirects already.

The official SDK examples named `generate_speech` and `generate-speech` use the
ordinary complete-response workflow. The `stream_audio` and `stream-audio`
examples consume the same binary response progressively, allowing playback or
file writes before the complete response has downloaded.

For explicit event boundaries, request SSE:

```bash
# -N disables cURL buffering so SSE events appear as they arrive.
curl -L --fail-with-body -sS -N \
  https://api.kittenml.com/v1/audio/speech \
  -H "Authorization: Bearer $KITTENML_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{
    "model": "kitten-tts-2-latest",
    "input": "The first phrase can play while the next phrase is generated. This keeps long speech responsive.",
    "voice": "eleanor_en",
    "response_format": "mp3",
    "stream_format": "sse"
  }'
```

Decode and concatenate each Base64 `speech.audio.delta` in order. The final
`speech.audio.done` event confirms that the audio is complete.

## Quality over speed

By default, Kitten TTS 2 is tuned for speed, for the lowest latency. For
quality over speed, add `"stream": false`. The API then returns one complete
file with higher audio quality, sent once the whole text has been generated.
It works with every `response_format` and cannot be combined with
`stream_format: "sse"`.

```bash
curl -L --fail-with-body -sS \
  https://api.kittenml.com/v1/audio/speech \
  -H "Authorization: Bearer $KITTENML_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{
    "model": "kitten-tts-2-latest",
    "input": "The harbor lights came on one by one as the fog rolled in.",
    "voice": "eleanor_en",
    "response_format": "wav",
    "stream": false
  }' \
  --output kitten-complete.wav
```

With the OpenAI SDKs, pass it as an extra field: `extra_body={"stream": False}`
in Python, or `stream: false` in JavaScript. The [`upload/`](upload/) examples
send it when `KITTENML_TTS_STREAM=false` is set.

## Pick a kitten

- `kitten-tts-2-latest` — Kitten TTS 2, the latest model, with 173 voices
- `kitten-tts-nano-0.8`
- `kitten-tts-micro-0.8`
- `kitten-tts-mini-0.8`

Kitten TTS 2 can also clone a voice; see the
[cloning guide](https://docs.kittenml.com/tts/custom-voices).

All four models use the same request shape. Voices belong to a
model: Kitten TTS 2 uses the voice IDs below, and the three 0.8 models
use `Bella`, `Jasper`, `Luna`, `Bruno`, `Rosie`, `Hugo`, `Kiki`, and `Leo`.
Start with Kitten TTS 2, then let Nano and Micro surprise you.

Non-streaming requests (`stream: false`) return at most 30 minutes of audio.
If the text would run longer, the file ends at the last complete sentence chunk
before 30:00, the response carries the header
`x-kittenml-audio-limit-reached: 1`, and only the delivered text is billed.
Output duration depends
on the input text, selected voice, and `speed`; HTTP input is limited to 40,000
characters.

curl -L --fail-with-body -sS \
  'https://api.kittenml.com/v1/voices?model=kitten-tts-2-latest' \
  -H "Authorization: Bearer $KITTENML_API_KEY" \

instead of `\u` escapes, so they can be copied into a request.

Select a language with its voice; there is no separate language field. Write
the input in that language. Check each voice's `language` and `experimental`
fields in the listing.

Kitten TTS 2 reads numbers, dates, currencies, and times as words in the
selected voice's language: `12` becomes `twelve` with an English voice and
`बारह` with a Hindi voice. Set `normalize` to `basic` (the default), `smart` for
context-aware readings with added latency, or `no` to turn it off. Swedish,
Danish, Finnish, and Hebrew normalization currently keep the input text, so
write numbers, dates, and currencies as words in those languages when exact
pronunciation matters. The KittenTTS 0.8 models normalize English only.

## Emotion and sound tags

Kitten TTS 2 reads three kinds of inline markup in `input`. The KittenTTS 0.8
models read bracketed text aloud as ordinary words.

| Markup | Supported values | Where to put it |
| --- | --- | --- |
| Emotion tag | `[joyful]`, `[excited]`, `[tender]`, `[sad]`, `[angry]`, `[nervous]`, `[stern]`, `[surprised]`, `[contemplative]`, `[mundane]` | Before the sentence it should color |
| Sound tag | `<laugh>`, `<giggle>`, `<sigh>`, `<gasp>`, `<sob>`, `<scoff>`, `<growl>`, `<um>`, `<gulp>`, `<pause>` | Where the sound should happen |
| Emphasis | `(((word or short phrase)))` | Around the words to stress |

```bash
curl -L --fail-with-body -sS \
  https://api.kittenml.com/v1/audio/speech \
  -H "Authorization: Bearer $KITTENML_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{
    "model": "kitten-tts-2-latest",
    "input": "[excited] We shipped it! <laugh> It is (((really))) fast.",
    "voice": "maeve_en"
  }' \
  --output kitten-output-tags.mp3
```

Tags are case-insensitive, and neither tags nor the emphasis parentheses are
read aloud. Any other bracketed text, such as `[happy]` or `<laughs>`, is read
as ordinary words. Emphasis needs exactly three parentheses on each side
around at most 80 characters on one line. Tags work on the realtime WebSocket
too. This feature is experimental: its effect may be subtle and can change
pacing, so preview the exact voice and text before using markup in production.

## Request fields

| Field | Required | Default | Accepted values |
| --- | --- | --- | --- |
| `model` | No | `kitten-tts-mini-0.8` | One of the four IDs above |
| `input` | Yes | — | Non-empty text, up to 40,000 characters |
| `voice` | No | Model-specific | A voice ID of the selected model as a string, such as `eleanor_en` or `Bella`, a saved Kitten TTS 2 voice as `{"id": "voice_..."}`, or a Kitten TTS 2 inline reference object (see the [cloning guide](https://docs.kittenml.com/tts/custom-voices)) |
| `response_format` | No | `mp3` | `mp3`, `wav`, `flac`, `aac`, `opus`, or `pcm` |
| `stream_format` | No | `audio` | `audio` for binary chunks or `sse` for Base64 events |
| `speed` | No | `1.0` | `0.25` through `4.0` |
| `normalize` | No | `basic` | Kitten TTS 2 only: `basic`, `smart`, or `no` (`true` and `false` also work) |
| `stream` | No | `true` | Kitten TTS 2 only: `false` returns one complete file with higher audio quality; see [Quality over speed](#quality-over-speed) |
| `mode`, `temperature`, `top_p`, `top_k`, `min_p`, `max_new_tokens` | No | From `mode` (`expressive`) | Kitten TTS 2 only; see [`controls/`](controls/) |

Omit `voice` to use the selected model's default; do not send
`"voice": null`:

| JSON request | Effective default |
| --- | --- |
| `model: "kitten-tts-2-latest"`, no `voice` | `eleanor_en` |
| Any KittenTTS 0.8 `model`, no `voice` | `Bella` |
| No `model` and no `voice` | `kitten-tts-mini-0.8` with `Bella` |

A request without `model` is served by `kitten-tts-mini-0.8`, so name
`kitten-tts-2-latest` in every Kitten TTS 2 request.

`pcm` returns headerless 24 kHz, mono, signed little-endian PCM16. Some media
libraries interpret the `audio/L16` response name as big-endian, so use `wav`
for portable PCM interchange or explicitly configure the raw-audio reader for
little-endian data. Other formats stream the matching encoded format.

## Test every model

```bash
# Run the same request shape against each supported model.
for MODEL in \
  kitten-tts-2-latest \
  kitten-tts-nano-0.8 \
  kitten-tts-micro-0.8 \
  kitten-tts-mini-0.8
do
  # Each model has its own voices.
  if [ "$MODEL" = "kitten-tts-2-latest" ]; then
    VOICE="eleanor_en"
  else
    VOICE="Bella"
  fi
  # Keep each result separate so you can compare quality and latency.
  curl -L --fail-with-body -sS \
    https://api.kittenml.com/v1/audio/speech \
    -H "Authorization: Bearer $KITTENML_API_KEY" \
    -H "Content-Type: application/json" \
    --data "{\"model\":\"$MODEL\",\"input\":\"Testing $MODEL.\",\"voice\":\"$VOICE\",\"response_format\":\"wav\"}" \
    --output "$MODEL.wav"
done
```

## Pick a workflow

| Workflow | Input | Output | Examples |
| --- | --- | --- | --- |
| Complete response | Complete HTTP request | Complete audio response | [`upload/`](upload/) |
| Output streaming | Complete HTTP request | Binary chunks or SSE events | [`streaming/`](streaming/) |
| Realtime | Incremental WebSocket messages | Audio events while input continues | [`realtime/`](realtime/) |
| Voice discovery | Model ID, optional filters | Kitten TTS 2 public voices, languages, and your saved voices; descriptions when searching | [`voices/`](voices/) |
| Decoding controls | Complete HTTP request with `mode`, `top_k`, and related fields | One audio file per preset | [`controls/`](controls/) |

Python and JavaScript examples share one setup at the TTS product root:

```bash
cd tts
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
npm install
cp .env.example .env
# Put your KittenML API key in .env.
```

The speech examples use Kitten TTS 2 with `eleanor_en` by
default. Set `KITTENML_TTS_MODEL` and `KITTENML_TTS_VOICE` in `.env` or your
shell to try another model or voice. When only the model is set to a
0.8 ID, the examples switch to `Bella`:

```bash
KITTENML_TTS_VOICE='maeve_en' python upload/generate_speech.py
KITTENML_TTS_MODEL=kitten-tts-mini-0.8 npm start
```

To use one of your saved Kitten TTS 2 voices, set `KITTENML_TTS_VOICE` to its
`voice_...` ID. The HTTP examples send it as `{"id": "voice_..."}`, and the
realtime examples put the ID in the `voice` query parameter:

```bash
KITTENML_TTS_VOICE='voice_0123456789abcdef0123456789abcdef' python upload/generate_speech.py
```

The complete-response examples use the official OpenAI SDKs. The streaming
examples show both progressive binary output and explicit SSE event handling.
The realtime examples use standard WebSocket clients because incremental text
input is a KittenML extension.

The WebSocket route is a KittenML extension for text produced over time. The
OpenAI-compatible HTTP endpoint receives complete input text. Its output can
be buffered as one complete response or consumed progressively.

HTTP requests have a 256 KiB JSON-body limit and a 30-minute timeout. For
predictable latency, keep each generation around 400–5,000 characters.

An organization can run two TTS generations at once, over HTTP and WebSocket
together. A request above that returns `429` with `Retry-After: 1`. Separately,
a Kitten TTS 2 request that arrives while generation capacity is momentarily
full can wait up to about 8 seconds before its audio starts; if no slot frees
up, it returns `503` with `Retry-After`. Retry both with backoff.
Input-streaming WebSockets accept 262,144 cumulative characters per session,
8,192 characters per append, and 64 KiB per frame. Send 50–500 characters at a
time, preferably complete phrases. Sessions close after five idle minutes or
two total hours.

For complete-response SDK usage, binary streaming, and SSE streaming, the
40,000-character hard limit is the same. Keep normal requests around 400–5,000
characters, and require `speech.audio.done` before accepting an SSE stream as
complete.

Try a few voices, test a longer sentence, and have fun with it. Happy meow-ing. ^^
